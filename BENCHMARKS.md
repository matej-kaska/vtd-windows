# Local validation

Resampling now reuses phase filter coefficients. An optimized standalone comparison of the previous and current functions on 14 s of generated audio, three repetitions, measured 246.150–265.782 ms versus 16.704–17.075 ms at 48 kHz, with identical output samples. At 44.1 kHz it measured 213.285–225.564 ms versus 15.234–15.783 ms; maximum absolute sample difference was 3.73e-9. This is preprocessing time only, not end-to-end dictation latency; model and decoding settings are unchanged.

One user-authorized 14.100 s microphone sample produced identical complete text with Q5, Q8 and F16 (0.502, 0.724 and 0.516 s respectively). The previous decoder also produced the same text (0.505 s). This sample did not reproduce the reported repeated punctuation. The user reported correct insertion in Codex but broken output in a text editor; clipboard paste is now available as an alternative input path, pending verification in that editor. Standard temperature fallback (increment 0.2) has been restored; it was previously disabled. Raw audio and transcripts are excluded from the repository.

After reports of missing words in real dictation, the decoder was changed to beam search (width 5) and microphone release now includes a 250 ms capture tail. With the Q5 model, three repetitions took 0.285–0.340 s for the short sample and 0.606–0.670 s for the long sample. Text was unchanged on these synthetic samples. A 55.742 s concatenation of the long sample retained all three copies (1.644 s inference). This rules out a general 30-second truncation on that input, but does not establish the cause of missing words in microphone dictation. Capture diagnostics now report device, captured duration, elapsed duration and RMS without saving audio or transcript. Natural-speech improvement is not yet verified.

## Earlier greedy baseline

Measured on 2026-09-29, Windows, AMD Radeon RX 7800 XT, Ryzen 7 7800X3D. Release build, whisper-rs 0.16.0, Vulkan, flash attention, Czech (`cs`), greedy decoding, four CPU threads. GPU logs confirmed Vulkan0 model allocation and inference backend.

Two local synthetic Czech recordings generated by the installed Microsoft Jakub voice. These are smoke tests, not a representative Czech accuracy benchmark or a test of the user's microphone.

| Model | Model file | 5.279 s recording | 18.581 s recording |
| --- | ---: | ---: | ---: |
| large-v3-turbo Q5_0 | 574 MB | 0.189–0.191 s | 0.308–0.338 s |
| large-v3-turbo Q8_0 | 874 MB | 0.197–0.241 s | 0.308–0.314 s |
| large-v3-turbo F16 | 1,625 MB | 0.200–0.234 s | 0.337–0.345 s |

Ranges include all measured repetitions after startup warm-up: five for the short Q5 recording, three otherwise. Timing is inference only; microphone capture, resampling and insertion are excluded. Startup plus warm-up was 0.68–1.96 s with the driver cache already populated. The first uncached Q5 inference before startup warm-up was added took 2.033 s.

All three variants correctly transcribed the short sentence. On the longer recording all three omitted the final `i` in `Potřebuji` and formatted `deset` as `10`. Q5 is the default because the larger models did not improve these two samples. Wider evaluation on natural speech remains necessary.

The Windows hotkey and microphone opening were checked in the running background process. Automated tests cover silence/click rejection and anti-aliasing when resampling 44.1/48 kHz audio to 16 kHz. A full microphone-to-editor dictation, cross-application insertion, Strix Halo execution, and power draw in watts have not yet been verified.

After automatic model unloading, the background process used 67.2 MiB working set and 47.7 MiB private memory. During a 24.047 s idle observation, accumulated process CPU time did not increase at the counter's resolution. This is process memory/CPU evidence, not an electrical power measurement. No recording was saved.
